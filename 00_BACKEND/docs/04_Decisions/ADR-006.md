# ADR-006 — Gunakan Zustand untuk State Management, Bukan Redux

## Status

Diterima — **tidak diterapkan di kode** (catatan 2026-10-12).

> **Catatan verifikasi 2026-10-12:** `zustand` tidak ada di dependensi (`package.json`, `admin/package.json`) dan tidak ada store Zustand di `src/`. State global aktual memakai **React Context** + service layer. Keputusan "bukan Redux" tetap berlaku (Redux juga tidak dipakai). Perlu ADR baru bila tim ingin meresmikan pola Context atau tetap mengadopsi Zustand.

## Context

- Aplikasi butuh state global (auth, campaign, wallet, notification) tetapi tim kecil dan ingin iterasi cepat.
- Redux menuntut banyak boilerplate (actions, reducers, store setup).

## Decision

Gunakan **Zustand** sebagai library state management.

## Consequences

- (+) Lebih ringan, API sederhana, tanpa boilerplate Redux.
- (+) Mudah dipakai bersama service layer dan hooks.
- (−) Ekosistem middleware/devtools tidak sekaya Redux untuk kebutuhan kompleks di masa depan.

### Catatan implementasi (2026-10-12)

- Provider/context yang dipakai: `src/components/providers/AuthProvider.tsx`, `src/components/providers/TosConsentProvider.tsx`, `src/components/features/shared/NotificationProvider.tsx`, `src/components/features/creator-dashboard/CreatorIdentityContext.tsx`, `src/components/features/dashboard/UmkmIdentityContext.tsx`.
- Data server dibaca lewat service (`ServiceResult`) per halaman/komponen; form memakai `react-hook-form` + Zod.
- Status ADR ini perlu diputuskan ulang: diganti (superseded) oleh pola React Context, atau Zustand diadopsi sungguhan.
