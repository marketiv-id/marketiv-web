# ADR-004 — Pisahkan `fraud_checks` dari `campaign_submissions`

## Status

Diterima.

> **Catatan verifikasi 2026-10-12:** keputusan berlaku di kode (`ai-fraud-precheck`). Phase 2 (CV/logo/product) belum diimplementasikan.

## Context

- Submission membutuhkan hasil deteksi fraud (score, status, alasan).
- Phase 2 akan menambah jenis pengecekan: Computer Vision, Product Detection, Logo Detection.
- Menyimpan semua di dalam `campaign_submissions` akan membengkak dan sulit menyimpan histori banyak pengecekan.

## Decision

Pisahkan `fraud_checks` sebagai koleksi terpisah dengan relasi Submission 1 → N Fraud Checks. Field ringkas (mis. `fraudScore`, `fraudStatus`) tetap boleh ada di submission untuk query cepat.

## Consequences

- (+) Histori beberapa pengecekan fraud per submission dapat disimpan.
- (+) Phase 2 (CV/logo/product) bisa ditambahkan tanpa membengkakkan submission.
- (−) Perlu join/query tambahan untuk melihat detail histori fraud.

### Catatan implementasi (2026-10-12)

- `ai-fraud-precheck` (event `campaign_submissions.rows.*.create`) menulis ringkasan `fraudScore`/`fraudStatus` (`safe|review|rejected`) ke submission dan satu baris `fraud_checks` `{ submissionId, score, result, reason }` per eksekusi. Precheck hanya berjalan sekali per submission, jadi dalam praktik relasinya 1 → 1.
- Ringkasan fraud tidak pernah mengubah `submission.status`; keputusan final ada di Admin (lihat [ADR-010](ADR-010.md)).
- `fraud_checks` tanpa permission level koleksi (server-only). (−) Antrean Admin (`get-admin-submission-queue`) belum mengekspos skor maupun histori, sehingga data ini belum dipakai di UI.
