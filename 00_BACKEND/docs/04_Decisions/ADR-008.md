# ADR-008 — Platform Fee 2% (Per-Modul)

## Status

Diterima — **butir 3 & 4 diganti oleh implementasi T-01** (catatan 2026-10-12).

> **Catatan verifikasi 2026-10-12:** model per-modul (Rate Card seller-side, Campaign buyer-side) dan nilai default 2% tetap berlaku di kode. Namun fee **bukan lagi konstanta hardcode**: sejak T-01 (2026-08-04, commit `c837e3a`) Function membaca env `FEE_RATE` (default `0.02`) dan escrow menyimpan snapshot `fee_rate`. Cron `fee-rate-flip` memantau ambang 1.000 transaksi `completed` dan memberi tahu Admin untuk menaikkan `FEE_RATE` ke `0.05` secara manual di Console. Pencatatan fee Campaign juga berbeda dari butir 2 (lihat Catatan implementasi).

## Context

- Marketiv membutuhkan sumber pendapatan (revenue stream) untuk keberlanjutan platform.
- Dua sumber transaksi utama: **Rate Card Order** (escrow) dan **Campaign PPV** (top-up budget).
- Dua opsi pembebanan fee yang dipertimbangkan:
  1. **Buyer side (UMKM)** — fee ditambahkan ke total pembayaran UMKM. Creator terima full amount.
  2. **Seller side (Creator)** — fee dipotong dari pendapatan creator.
- Dua metode penerapan yang dipertimbangkan:
  a. Persentase tetap dari nominal transaksi.
  b. Flat fee per transaksi.
- Keputusan akhir: **per-modul**, disesuaikan dengan nature transaksi:
  - Rate Card Order → **seller side** — UMKM bayar sesuai harga rate card, fee dipotong dari pendapatan creator. Alasannya: rate card adalah etalase creator, wajar jika creator menanggung fee platform.
  - Campaign PPV → **buyer side** — fee ditambahkan ke total top-up UMKM, creator terima reward full. Alasannya: campaign budget adalah dana yang dikelola platform untuk reward, fee terpisah dari reward.

## Decision

1. **Fee 2%** (persentase tetap), dengan model per-modul:
   - **Rate Card Order**: fee dipotong dari **seller side (creator)**.
     ```
     UMKM bayar: hargaPaket
     Escrow:     hargaPaket
      Saat release: creator terima hargaPaket - floor(hargaPaket × 2%)
                   platform catat fee floor(hargaPaket × 2%)
     ```
   - **Campaign Top-Up**: fee dibebankan ke **buyer side (UMKM)**.
     ```
      totalBayar = budget + floor(budget × 2%)
      Budget penuh RpX untuk reward creator
      Fee platform = floor(budget × 2%)
     ```
2. Fee dicatat sebagai transaksi `fee` di ledger (`transactions`) tanpa memengaruhi wallet user.
3. Nilai fee ditetapkan sebagai **konstanta sistem** (`PLATFORM_FEE_RATE = 2`), mengikuti pola ADR-007.
4. Tidak ada mekanisme perubahan fee via UI/Admin pada MVP. Perubahan nilai memerlukan update kode + redeploy.

## Consequences

- (+) Sesuai nature bisnis — rate card creator punya insentif menaikkan harga, campaign UMKM bayar biaya platform.
- (+) Rate card: UMKM lihat harga sesuai rate card, tidak ada tambahan — konversi lebih tinggi.
- (+) Campaign: creator terima reward full tanpa potongan.
- (−) Rate card: creator terima lebih kecil dari harga rate card — perlu transparansi saat publish rate card.
- (−) Dua model berbeda = kompleksitas dokumentasi & implementasi lebih tinggi.
- (−) Perubahan fee butuh siklus deploy.

### Catatan implementasi (2026-10-12)

**Sumber rate (menggantikan butir 3 & 4):**

| Lokasi | Perilaku |
|---|---|
| `create-payment` (Campaign) | `fee_amount = floor(amount × FEE_RATE)`; `total_amount = amount + fee_amount` ditagih Midtrans; order Rate Card `fee_amount = 0` |
| `create-escrow` (Rate Card) | Simpan `escrows.fee_rate = FEE_RATE` saat escrow dibuat (snapshot) |
| `release-escrow` | `rate = escrow.fee_rate \|\| 0.02`; `feeAmount = floor(amount × rate)`; kreator dikredit `amount − feeAmount` |
| `fee-rate-flip` (cron `0 0 * * *`) | Hitung `transactions.status = completed`; bila ≥ 1.000, log + notifikasi ke `ADMIN_NOTIFY_USER_ID` untuk flip manual ke `FEE_RATE=0.05`. Tidak mengubah env sendiri |
| `00_BACKEND/src/services/wallet.service.ts` | `PLATFORM_FEE_RATE = Number(NEXT_PUBLIC_FEE_RATE \|\| FEE_RATE \|\| 0.02)` |
| `src/types/domain.ts` (frontend) | `PLATFORM_FEE_RATE = 0.02` hardcode |

**Pencatatan fee (menyesuaikan butir 2):**

- Rate Card: ledger `transactions` `{ type: "fee", referenceType: "escrow", referenceId: escrowId, userId: creatorId, amount: feeAmount }`, berdampingan dengan ledger `release` bernilai bersih. Wallet kreator hanya dikredit nilai bersih.
- Campaign: fee **tidak** dicatat sebagai ledger `fee`; hanya tersimpan di `payments.fee_amount`/`total_amount`. Ledger top-up (`type: "payment"`, `referenceType: "payment"`) bernilai budget saja.

**Konsekuensi tambahan:**

- (+) Rate dapat diubah tanpa redeploy; escrow lama tetap memakai rate saat dibayar.
- (−) Frontend menampilkan 2% hardcode; bila `FEE_RATE` diubah, angka di UI dan pesan notifikasi rilis ("fee platform 2%" di `release-escrow`) tidak lagi akurat.
- (−) Pendapatan fee Campaign harus direkonsiliasi dari `payments`, bukan dari ledger `fee`.
