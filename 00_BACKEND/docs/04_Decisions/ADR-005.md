# ADR-005 — Simpan Counter Denormalisasi di `campaigns`

## Status

Diterima.

> **Catatan verifikasi 2026-10-12:** keputusan berlaku. Counter kini dijaga dengan increment/decrement atomik TablesDB di Function, dan browser tidak lagi punya izin `update` pada baris campaign.

## Context

- Dashboard UMKM dan job board sering menampilkan agregat campaign: total klaim, dana terpakai, sisa budget.
- Menghitung nilai-nilai ini dari koleksi lain (claims, transactions) setiap kali render mahal dan lambat.

## Decision

Simpan data denormalisasi langsung pada `campaigns`: `totalClaims`, `spentAmount`, `remainingBudget`. Nilai diperbarui oleh proses/Function saat event terkait terjadi, meski secara teknis dapat diturunkan dari koleksi lain.

## Consequences

- (+) Dashboard dan job board cepat tanpa agregasi mahal.
- (−) Ada risiko ketidaksinkronan; nilai harus dijaga konsisten lewat update terkontrol (Functions/service).
- (−) Tambahan tanggung jawab menulis counter di alur klaim/pembayaran.

### Catatan implementasi (2026-10-12)

Penulis counter (semua atomik via `functions/*/src/atomic.js`, server menegakkan `min`/`max`):

| Counter | Naik | Turun |
|---|---|---|
| `totalClaims` | `campaign-claimed` (+1, `max = claimLimit`; gagal kuota → claim `expired`) | `unclaim-campaign`, `expire-stale-claims`, `review-submission` (reject) (−1, min 0) |
| `remainingBudget` | `create-escrow` top-up campaign (+`payment.amount`) | `calculate-campaign-reward` (−reward, min 0); `refund-order` `{ campaignId }` (dinolkan) |
| `spentAmount` | `calculate-campaign-reward` (+reward) | — |

- Edit browser dibatasi: `patch-campaign-draft` (allowlist non-finansial) dan `patch-campaign-status` (publish/pause/resume); baris campaign hanya memberi `read` + `delete` ke pemilik (Fix SEC-H1, 2026-08-08).
- (−) Baris campaign masih dibuat langsung oleh browser (`campaigns` punya `create("users")`), sehingga nilai awal counter (`remainingBudget`, `totalClaims`, `spentAmount`, `status`) berasal dari payload klien dan tidak divalidasi server.
- (−) Ada jeda antara create claim (browser) dan increment di `campaign-claimed`; guard klien membaca counter basi.
